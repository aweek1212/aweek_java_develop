# 쇼핑몰 백엔드 로드맵

강의 진도에 맞춰 **하나의 쇼핑몰 프로젝트를 계속 리팩토링하며 키워 가는** 계획입니다.
새 개념을 배울 때마다 "지금 코드의 어떤 불편함을 이 개념이 해결하는가"를 직접 겪어 보는 것이 목표예요.

```
순수 자바 콘솔 쇼핑몰  ──(자바 기본·중급·고급)──▶  설계가 다듬어진 자바 쇼핑몰  ──(스프링)──▶  스프링 부트 REST API + DB
```

---

## 1부. 실전 자바 기본편

### 1단계. 기초 쇼핑몰 (섹션 2 ~ 8: 클래스, 참조형, 생성자, 패키지, 접근 제어자, static)

| 미션 | 내용 | 핵심 개념 |
|---|---|---|
| [미션 1](missions/mission-01-member.md) | 회원 도메인: 회원 가입, 중복 검사, 조회 | 클래스, 생성자, `this()`, 패키지, 캡슐화, static 변수·메서드, null |
| 미션 2 | 상품 도메인: 상품 등록, 재고 증가·감소 (재고는 음수가 될 수 없음) | 캡슐화로 규칙 지키기, 객체에 기능 넣기 |
| 미션 3 | 주문: 회원이 상품을 주문하면 재고가 줄고, 취소하면 복구 | 참조형으로 객체 연결, 여러 저장소를 쓰는 서비스 |
| 미션 4 | 콘솔 화면: `Scanner` 메뉴로 가입·상품 등록·주문 | 화면 계층 분리, `main`에서 객체 조립 |

이 단계가 끝나면 이런 구조가 됩니다. 스프링 부트 프로젝트와 같은 계층 구조예요.

```
ShopMain (조립·실행)
  └─ 화면(콘솔)      → 나중에 @RestController
       └─ 서비스      → 나중에 @Service
            └─ 저장소  → 나중에 @Repository + DB
                 └─ 도메인 → 나중에 @Entity
```

### 2단계. final (섹션 9)
- 최대 저장 개수, 메뉴 번호 같은 값을 **상수**로 바꾸기
- 서비스가 가진 저장소 필드를 `final`로 만들어 바뀌지 않게 하기 (스프링의 생성자 주입 방식과 같음)

### 3단계. 상속 (섹션 10)
- 상품을 **도서·음반·영화**로 나누기: `Book`, `Album`, `Movie extends Item`
- `super(...)` 생성자로 공통 필드 초기화, 상품 정보 출력을 메서드 오버라이딩으로

### 4단계. 다형성 (섹션 11·12)
- 상품 배열을 부모 타입 `Item[]` 하나로 다루기, `instanceof`와 다운캐스팅
- `Item`을 추상 클래스로
- **저장소를 인터페이스로 분리**: `MemberRepository` (역할) / `MemoryMemberRepository` (구현)

### 5단계. 다형성과 설계 (섹션 13)
- **할인 정책** 인터페이스: 정액 할인 ↔ 정률 할인을 코드 수정 없이 갈아끼우기 (OCP)
- 객체 생성과 연결을 `AppConfig`로 분리 → 스프링 DI 컨테이너가 하는 일을 손으로 먼저 해 보기

> 기본편을 완강하면 스프링 핵심 원리 강의의 예제와 거의 같은 구조를 **직접 만들어 본 상태**가 됩니다.

## 2부. 실전 자바 중급·고급편

### 6단계. 중급 1편
| 배울 개념 | 쇼핑몰에 적용 |
|---|---|
| `Object` (`toString`, `equals`) | 도메인 객체 출력·비교 |
| 불변 객체 | 주소(`Address`) 같은 값 객체 |
| 래퍼 클래스 | `long id` → `Long id` (아직 저장 전이면 `null`) |
| `enum` | 회원 등급(`BASIC`, `VIP`), 주문 상태(`ORDER`, `CANCEL`) |
| 날짜와 시간 | 주문 시각 기록 |
| 예외 처리 | `null` 반환과 `println` 실패 메시지 → **사용자 정의 예외** (재고 부족, 중복 회원 등) |

### 7단계. 중급 2편
- **제네릭, 컬렉션**: 크기가 고정된 배열 저장소 → `ArrayList` / `HashMap` 저장소
- 주문 한 번에 상품 여러 개 담기 (`OrderItem`), 장바구니

### 8단계. 고급 1~3편 (배운 만큼 골라서 적용)
| 배울 개념 | 쇼핑몰에 적용 |
|---|---|
| 멀티스레드와 동시성 | 여러 명이 동시에 주문할 때 재고가 꼬이는 문제와 해결 |
| I/O | 파일에 저장하는 `FileMemberRepository` (인터페이스 덕분에 서비스 코드는 그대로) |
| 네트워크, HTTP 서버 | 콘솔 대신 브라우저에서 상품 목록 조회 |
| 리플렉션, 애노테이션 | 아주 작은 DI 컨테이너 직접 만들기 |
| 람다, 스트림 | 검색·정렬·매출 통계 |

## 3부. 스프링 부트

### 9단계. 스프링으로 옮기기
- Gradle 기반 스프링 부트 프로젝트로 전환
- `AppConfig` → `@Configuration` / `@Bean` → 컴포넌트 스캔 (`@Service`, `@Repository`)
- 콘솔 화면 → **REST API** (`@RestController`, JSON)
- 메모리 저장소 → H2 DB (JDBC → JPA → 스프링 데이터 JPA)
- 콘솔 확인 코드 → JUnit 테스트

각 단계의 미션 문서는 그 단계 강의를 들은 뒤에 만들어요. 그래야 실제로 배운 개념만으로 설계할 수 있어요.
